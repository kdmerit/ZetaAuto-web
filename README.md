# ZetaAuto 웹 백테스트

`kdmerit/ZetaAuto-web`의 GitHub Pages에서 모바일 앱의 백테스트 메뉴를 제공하는 정적 React 앱입니다. 현재 웹 버전은 v2.10.41입니다.

- 개별·전체 종목·장기 분석: Bybit 공개 시세와 IndexedDB 캔들 캐시를 사용해 Web Worker로 계산합니다.
- 전체 종목은 하나의 가상 계좌를 공유합니다. 종가 진입 전략은 청산 후 진입하며, 봉 중간 돌파는 종목명 순서·봉 시작 가용자금 한도로 배분합니다.
- 진행 상태·완전한 분석 결과·캔들: IndexedDB, 마지막 설정·이력 요약: localStorage에 저장합니다.
- 변동성 돌파: 직전봉 몸통 크기를 변동폭으로 사용해 K1 돌파에 봉 중간 진입하며 진입 시점 SL·선택형 K1 TP·다음 봉 종가 청산을 적용합니다.
- 엔벨로프: 4개 주기·8개 SMA와 0.1~20.0% 이격의 하단 롱·상단 숏 접촉 진입, 실제 매수가 기준 같은 비율 SL, 세 가지 밴드 청산 방식을 제공합니다.
- 엔벨로프의 개별분석·전체분석·개별통계·전체통계는 별도 화면입니다. 통계는 입력한 레버리지를 고정하고 주기·SMA·이격·청산 방식만 비교합니다. 전체통계 결과로 공유 계좌 가상매매를 실행할 수 있습니다.
- 눌림목·이격매매의 공개 시세 접근 오류는 `서버에서 분석`으로 기존 인증된 AWS 작업을 선택할 수 있습니다. 새 변동성 돌파·엔벨로프는 로컬 전용이며, 지원하지 않는 AWS 계산으로 잘못 전환하지 않습니다. 기존 서버 이력·차트는 계속 읽습니다.
- 웹앱에는 AWS 자격증명이나 Google Client Secret을 넣지 않습니다.

v2.10.27은 신규 상장 종목의 등록 시각과 실제 첫 캔들 시각 차이로 전체 분석이 멈추는 문제를
수정합니다. 예를 들어 CTUSDT는 2026-10-01 17:45:28 KST에 등록됐지만 첫 1시간봉은
18:00 KST부터 있습니다. 공개 응답으로 확인된 상장 초기 빈 구간만 저장해 건너뛰고 실제
첫 캔들부터 사용합니다. 기존 2.10.26 계좌 스냅샷과 진행 상태를 그대로 이어갈 수 있습니다.
중간 구간의 실제 누락은 해당 봉을 한 번 더 조회하고, 복구되지 않으면 오류로 표시합니다.

## 개별통계·전체통계 분석 주기 선택 (v2.10.41)

두 통계 화면의 `통계 분석 주기`에서 `15m`·`1h`·`4h`·`1d`·`전체` 중 하나를 선택합니다.
기본값은 기존과 같은 `전체`입니다. 한 주기를 고르면 해당 주기의 캔들만 조회·계산하며,
결과를 나중에 필터링하는 방식이 아닙니다. 8개 SMA × 이격 200단계 × 청산 3방식의
최대 4,800개 조합을 비교하고, `전체`는 네 주기의 최대 19,200개를 비교합니다. 밴드 접촉이
없는 더 넓은 이격은 기존처럼 건너뜁니다. 선택 주기의 완성봉이 10개 미만이면 시작 전에
기간을 늘리도록 안내하며, 전체 선택에서는 분석 기간이 부족한 상위 주기만 제외합니다.

개별통계·전체통계의 마지막 선택은 각각 저장합니다. 결과·이력 카드에도 주기를 표시하며
이력을 열면 당시 선택을 복원합니다. 비교 그래프에는 실제 계산한 주기만 표시합니다.
입력한 고정 레버리지는 그대로 유지하고 자동 배율 탐색이나 최대 한도 조회는 하지 않습니다.

새 통계·전체통계·가상매매 작업 버전은 2.10.41입니다. 기존 2.10.40 고정 배율 작업은
완료한 조건·종목을 보존한 채 같은 ID로 이어가며, 저장 당시의 `전체` 주기·배율을 유지합니다.
새 작업도 이어하기에서는 폼의 변경값 대신 저장된 주기·배율을 사용합니다. 이전 0건 작업의
전환에는 현재 입력한 주기·배율을 적용합니다. 2.10.40 완료 전체통계도 가상매매 원본으로
사용할 수 있습니다. 가상매매는 원본 통계의 주기에 맞춰 완성봉 기간을 정렬하되 실행 축은
계속 15분봉을 사용합니다. 이력·캔들·일반 분석은 보존하며 Pages만 갱신합니다.

## 통계의 사용자 입력 고정 레버리지 (v2.10.40 도입, 현재도 유지)

개별통계·전체통계에 `고정 레버리지` 입력란을 제공합니다. 1~100배, 소수 둘째 자리까지
입력할 수 있으며 5를 입력하면 모든 주기·SMA·이격·청산 방식 조합을 5배로 계산합니다.
레버리지를 1씩 올리는 최적화·최대 한도 조회·risk-limit/유지증거금 조회·단위 추측 검사는
삭제했습니다. ‘최적 레버리지’ 비교 지표 대신 결과의 실제 적용 배율만 표시합니다.
새 결과에는 이전 자동 탐색의 위험한도 스냅샷도 적용하지 않습니다.

SL·수수료·슬리피지·가용자금을 반영하는 일반 분석과 같은 계좌 엔진입니다. 거래소 최대
배율이나 실제 계좌의 강제청산·펀딩비를 재현/검증하는 기능은 아닙니다. 입력한 배율을
가정하는 모의 계산이며 특히 큰 배율에서는 실제 거래소 체결·손실 범위와 다를 수 있습니다.

전체통계는 슬리피지 필터 없는 모든 활성 USDT 종목을 동일한 입력 배율로 분석하고 종목당
최고 수익률 세팅 하나씩을 저장합니다. 가상매매는 완료한 고정 배율 전체통계 보고서의
기간·초기자금·베팅액·레버리지를 그대로 사용해 한 공유 계좌에서 계산합니다.
선택한 세팅을 개별분석에 불러올 때에도 고정 배율을 유지합니다.

v2.10.40에서 통계·전체통계·가상매매 작업을 고정 배율로 전환했습니다. 이전 완료 보고서·이력·캔들은
보존하지만 자동 배율과 고정 배율 결과를 섞지 않습니다. 0건에서 멈춘 이전 개별통계는
입력한 배율로 같은 ID에서 이어갈 수 있습니다. 전체통계도 완료 종목이 없으면 전환해
이어갑니다. 이전 방식으로 일부 결과가 완료된 작업은 새 분석을 시작해야 합니다.
기존 완료 전체통계 이력은 계속 읽지만 새 가상매매 원본에는 고정 배율 보고서만 선택합니다.
현재 방식으로 일시정지한 작업은 원래 저장된 배율을 유지해 재개합니다.

최근 30일·종류별 최대 20건의 통계 이력과 기존 localStorage/IndexedDB 저장 정책을
유지합니다. 일반 엔벨로프 2.10.36·변동성 2.10.31·다른 두 전략 2.10.26 작업도 보존합니다.
Pages만 배포하며 APK·AWS는 변경하지 않습니다. 이전 위험한도 스냅샷은 구결과 재현용으로만
읽고 새로운 조회는 하지 않습니다. 자동 배율 탐색 소스와 전용 무자금제한 추적 경로도 제거했습니다.

## 위험한도 응답 형식·0% 이어하기 수정 (v2.10.39 당시, v2.10.40에서 조회 제거)

최하위 위험등급의 `isLowestRisk`가 숫자 `1` 또는 문자열 `"1"`로 와도 동일하게 처리합니다.
해당 등급에 한해서 빈 `mmDeduction`(공란·null·누락)을 공제액 0으로 정규화합니다.
다른 등급·불명확한 등급의 누락 공제액은 0으로 대체하지 않습니다. 숫자 필드의 빈 문자열·
null·boolean을 숫자 0/1로 잘못 변환하지 않으며 실제로 잘못된 자료는 단계와 필드 이름을
표시하고 중단합니다. 비율 단위 검증과 임의 LIQ 사용 금지는 유지합니다.
고위험 상위 등급의 유지증거금률이 50% 이상이라는 이유만으로 종목 전체를 거부하던
임의 상한도 제거하고, 청산 수수료 포함 비율·공제액의 유효 범위를 검사합니다.

위험한도 로딩 중/실패를 ‘이전 고정 레버리지 통계’로 잘못 표시하지 않습니다. 실제 이전
버전 보고서에만 구버전 안내를 표시하고 새 작업은 확인 중·재조회 안내로 구분합니다.
일시정지 오류는 진행률과 안내문에 중복 출력하지 않고 한 번만 표시합니다.

페이지를 새로고침한 후 `개별통계 이어하기 · BTC`로 기존 0% 작업을 재개할 수 있습니다.
캐시·이력을 지우거나 새 분석을 시작할 필요는 없습니다. 정규화·표시 수정이므로 최적화/
전체통계/가상매매 계산 버전 2.10.38과 기존 작업 ID·완료 조건·보고서는 유지합니다.
공통 응답 처리 수정은 전체통계에도 적용하며 APK·AWS는 변경하지 않습니다.

## 엔벨로프 네 화면·레버리지 최적화·전체통계·가상매매 (v2.10.38 당시, 자동 배율은 v2.10.40에서 제거)

분석 대상은 `개별분석`·`전체분석`·`개별통계`·`전체통계` 네 버튼입니다. 기존 통계분석을
개별통계로 바꾸고 일반 분석의 폼·결과와 분리했습니다. 통계 카드를 누르면 기간·자금·
주기·SMA·이격·청산 방식·최적 레버리지를 불러와 개별분석으로 이동합니다. 한 화면에
통계와 일반 결과를 쌓지 않습니다. 기존 일반 분석 이력도 개별/전체 대상에 맞춰 복원합니다.
이전 일반 작업이 일시정지돼 있어도 새로 고른 통계 세팅을 우선 불러오고 기존 작업은
별도 이어하기로 유지합니다. 가상매매 화면에 먼저 이동해도 전체통계 완료 시 원본 목록을 갱신합니다.

개별통계는 4개 주기 × 8개 SMA × 이격 0.1~20.0%(0.1 단위) × 3개 청산 방식마다
레버리지를 1부터 종목의 공개 최대값까지 정수로 올려 비교합니다. 해당 이격에서 밴드
접촉 자체가 없어지면 더 넓은 이격을 건너뜁니다. 각 조건의 실제 거래가 있는 레버리지 중
최고 수익률 하나를 그래프·카드에 남기며 동률이면 낮은 레버리지를 우선합니다.

Bybit 공개 `instruments-info`·`risk-limit`에서 최대 레버리지·위험한도·유지증거금률·
공제액을 조회해 24시간 캐시합니다. 베팅액에 따른 위험한도와 다음 안전 조건을 모두
만족하는 레버리지만 비교하고, 처음 위반한 지점에서 증가를 멈춥니다. 롱+숏은 양쪽을
모두 만족해야 합니다. 메타데이터를 임의 값으로 대체하지 않습니다.

- 롱: `예상 LIQ ≤ SL × 0.997`
- 숏: `예상 LIQ ≥ SL × 1.003`

LIQ는 추가 증거금 없는 **격리마진 예상치**입니다. 진입가 P·수량 q·남은 증거금 M·
유지증거금률 m·공제액 D·청산 수수료율 f=0.00055일 때 롱은
`(Pq−M−D)/(q×(1−m−f))`, 숏은 `(Pq+M+D)/(q×(1+m+f))`로 계산합니다.
현재 공개 위험한도를 사용하므로 실제 계좌의 교차마진·마크가격·과거 거래소 청산가와
다를 수 있습니다. 시가 갭이 SL·LIQ를 모두 넘으면 남은 격리 증거금을 소진하는 추정
청산으로 처리하며, 기록된 정산 가격이 실제 거래소 체결가라는 의미는 아닙니다.

전체통계 안에는 `전체통계분석`·`가상매매`가 있습니다. 전체통계분석은 일반 전체분석의
주간 슬리피지 목록과 달리 **필터 없이 모든 활성 USDT 종목**을 대상으로 같은 탐색을
수행합니다. 종목당 최고 수익률 세팅 하나만 저장·표시하며 레버리지도 포함합니다.
각 종목의 비교 계좌는 독립적이므로 수익률을 합산하지 않습니다. 체결 없음·위험한도 자료
지원 불가는 별도 표시하고 일시적인 시세 조회 실패는 저장 지점에서 일시정지합니다.

가상매매는 완료된 전체통계 이력을 먼저 선택해야 실행할 수 있습니다. 해당 보고서의
기간·초기자금·고정 베팅액과 종목별 최적 세팅·당시 위험한도 자료를 사용합니다.
15분봉의 공통 시간축에서 종목별 원래 중심선 주기의 확정 종가만 투영하고, 하나의 공유
계좌로 자금을 배분합니다. 같은 원주기 봉의 재진입·미래 청산자금 재사용을 막으며 자금
부족 진입은 제외합니다. 더 세밀한 15분봉 재검증이므로 원주기별 독립 통계 합계와 다를 수
있습니다. 최종 수익률·평가액·실현손익·승률·진입/청산·낙폭·미청산·자금부족·추정 LIQ를 표시합니다.
**같은 기간에서 고른 최적값을 재사용하는 사후 분석이며, 미래 성과 검증이 아닙니다.**

진행은 Worker와 IndexedDB에 저장하며 일시정지·이어하기를 지원합니다. 일반 분석·
개별통계·전체통계·가상매매는 같은 Web Lock/임대로 중복 계산을 막습니다. 메뉴 이동 중에는
계속할 수 있지만 화면 잠금·탭 종료 후 실행은 보장하지 않습니다. 각 통계 종류의 이력은
최근 30일·최대 20건이며, 이력 읽기는 최신 일시정지 작업을 덮어쓰지 않습니다.

전체 최적 세팅 요약은 localStorage의 `zetaauto.web.envelope.allStatistics.latest`에,

## 변동성 돌파 조건 (v2.10.31)

`R = |직전 종가 − 직전 시가|`로 꼬리를 제외한 몸통 크기를 사용합니다.
`변동폭(%) = R ÷ 직전 종가 × 100`이며 최소 비율은 0.1~10.0%(기본 0.5)입니다.
K1·K2는 각각 0.1~10.0, K1≤K2이며 기본값 0.5·1.0은 유지합니다.

롱은 전전봉 음봉·직전봉 양봉을 확인하고 현재가가 `현재 시가 + R×K1`에 처음 닿을 때
진입합니다. 이 순간 양봉이며 `직전 저가 < 진입 시점까지의 현재봉 저가`여야 합니다.
숏은 전전봉 양봉·직전봉 음봉, `현재 시가 − R×K1`의 첫 하향 접촉,
`직전 고가 > 진입 시점까지의 현재봉 고가`를 확인합니다. 최종 종가·최종 꼬리를
미리 사용하지 않습니다. 1분봉 시가 갭이 K2 범위를 벗어나면 추격 진입하지 않습니다.

- `TP (변동폭 × K1)`: 기본 ON. 롱 `실제 매수가 + R×K1`, 숏 `실제 매수가 − R×K1` 접촉 시 종가를 기다리지 않고 전량 지정가 청산합니다.
- `매수 다음 캔들 종가 청산`: 기본 OFF. 진입한 선택 주기 봉의 바로 다음 봉 마감에 전량 시장가 청산합니다. 다음 1분봉이 아닙니다.
- 두 옵션은 독립적이며 먼저 충족한 조건으로 청산합니다. 둘 다 끄면 SL만 적용합니다.
- SL은 진입 시점까지의 현재봉 저가(롱)·고가(숏)로 고정하고 진입 직후부터 적용합니다.
  진입봉 안에서도 TP·SL 체결이 가능하되 진입 전 움직임으로 소급 청산하지 않습니다.

신호봉의 1분봉을 공개 API·IndexedDB에서 받아 시간순으로 확인하고, 각 1분봉의 두 OHLC
경로 중 불리한 결과를 사용합니다. 이후 보유 봉의 TP/SL 동시 접촉도 기존 부모봉 OHLC
경로로 보수적으로 처리합니다. 정확한 틱 재현은 아닙니다. 진입 시각은 해당 1분봉 시작,
이후 봉의 TP/SL은 선택 주기 봉 시작 시각의 추정치이며 다음 봉 종가 청산은 실제 마감
시각입니다. 차트 마커는 선택 주기 봉에 표시합니다. 1분봉 누락·부모봉 OHLC 불일치는
일시정지하며, 없는 데이터를 보간하거나 큰 봉 추정으로 조용히 대체하지 않습니다.

한 종목은 봉당 최대 한 번 진입하며 봉 시작에 보유했다면 그 봉 재진입은 제외합니다.
전체종목은 종목명 순서와 봉 시작 가용자금 한도로 배분해 같은 봉의 미래 청산 자금을
재사용하지 않습니다. SL 갭은 시가에 손절합니다. 시장가 슬리피지 0.02%·편도 수수료
0.055%는 유지하며 종료 시 미청산분은 평가액에 포함합니다.

두 체크 상태도 설정·이력에 저장합니다. TP OFF의 차트에는 TP 선을 표시하지 않으며
매수가 주황·SL 빨강은 유지합니다. 신호봉 1분봉도 기존 30일·최대 2GiB/브라우저 할당량
캐시 정책으로 관리합니다. 최초 분석에 필요한 1분봉을 추가 조회하고 이후에는 재사용합니다.

변동성 돌파 작업 버전은 2.10.31입니다. 2.10.30을 포함한 이전 미완료 작업은 새 분석이 필요하지만 기존
이력·결과·캔들은 지우지 않습니다. 눌림목·이격매매는 2.10.26 작업을 그대로 이어갑니다.
AWS 구조건 대체 실행은 계속 차단합니다. Pages만 배포하며 AWS·APK는 변경하지 않습니다.

화면 잠금·백그라운드·탭 종료는 브라우저에 의해 중단될 수 있으며, 재진입 시 자동으로 무거운
계산을 시작하지 않고 저장 지점의 이어하기 버튼을 표시합니다. 여러 탭의 중복 계산은 Web Locks와
구형 환경의 IndexedDB 임대로 막습니다.

캔들은 종목·주기·1,000봉 페이지로 보관하며 필요한 페이지와 없는 구간만 읽고 조회합니다.
기존 v1 구간 캐시는 한 구간씩 이관하고, 512구간 제한은 제거했습니다. 캐시 상한은 2GiB와
브라우저 추정 할당량의 60% 중 작은 값입니다. 최근 사용 후 30일이 지나거나 용량이 넘으면
오래된 페이지부터 정리하고 실제 할당량 초과 시 오래된 일부를 비운 뒤 한 번 재시도합니다.
이력은 최근 30일·전략별 최대 100건이며 완전한 결과는 IndexedDB에서 복원합니다.
새 탭이 저장소 업그레이드를 기다린다는 메시지를 보이면 기존 백테스트 탭들을 닫고 다시 엽니다.

회귀 검증은 Python Decimal 엔진에서 생성한 롱·숏·부분 TP·2차 체결 기준값과 비교합니다.
수백 종목 캐시, 공유 자금 부족, 체크포인트 복원·중복 방지, 누락 캔들 추가 조회를 테스트합니다.

## 앱 안에서 사용

ZetaAuto v2.10.24부터 백테스트 탭은 Chrome 맞춤 탭으로 이 페이지를 엽니다.
동일 휴대폰·동일 Chrome 프로필의 일반 탭과 localStorage·IndexedDB를 공유하므로
설정·분석 이력·캔들 캐시를 함께 사용합니다. 설정 변경은 즉시 저장하며 다른 탭의 변경도
탭 복귀·storage 이벤트에서 반영합니다. 다른 기기·시크릿 모드·다른 프로필과의 동기화는 아닙니다.
v2.10.22까지의 WebView 저장소에 있던 데이터는 자동으로 Chrome에 복사하지 않습니다.

앱은 AES-256-GCM으로 단기 세션을 암호화하고 JWT 보호 API에 암호문만 60초 동안 맡깁니다.
Chrome은 일회성 ID와 키를 URL fragment에서 받은 즉시 지우고, 키 증명으로 한 번만
암호문을 받아 복호화합니다. 실제 JWT는 `/session`에서 생성자 계정과 다시 대조합니다.
Access Token·Refresh Token은 URL·localStorage·IndexedDB에 넣지 않으며 앱 갱신 토큰은 전달하지 않습니다.
이미 Chrome 탭에 웹 OAuth 갱신 세션이 있으면 이를 재사용합니다. 앱 단기 토큰만 받은 새 탭은
토큰 만료 후 인증 API가 필요할 때 기존 Google 브라우저 로그인으로 웹 세션을 획득합니다.
로컬 계산 중에는 인증 갱신을 위해 페이지를 자동으로 이동시키지 않습니다.

이전 v2.10.21–v2.10.22 앱의 WebView 연결은 호환을 위해 유지합니다.
앱은 로그인된 사용자의 짧은 수명 Access Token을 메시지로 전달하며, 웹은 서버의 `/session`
검증 후 별도 로그인 없이 화면을 엽니다. 웹뷰의 단기 토큰은 메모리에만 두고 Refresh Token은
앱의 보안 저장소에 유지합니다. URL이나 웹 저장소에는 인증정보를 넣지 않습니다.
웹의 로그아웃은 앱 로그아웃으로 연결하고 뒤로가기는 차트·전략 화면부터 닫습니다.
일반 브라우저의 로그인 방식은 기존과 같습니다.

웹뷰 연결을 처음 설치한 이후 이 저장소의 화면·차트·웹 계산 변경은 Pages 배포만 하면 됩니다.
기본 로컬 백테스트 계산 변경은 Pages 배포로 반영합니다. 선택형 서버 계산을 변경할 때에는 AWS 배포도 필요하지만 APK 빌드는 필요하지 않습니다.
이전 WebView의 이력·설정·캔들 캐시는 Chrome과 별개이고, 새 Chrome 맞춤 탭은 Chrome 저장소를 사용합니다.

## 공개 저장소의 비밀정보 검사

소스와 전체 Git 이력, 실제 배포하는 `dist/`를 Gitleaks로 검사합니다. Pages 배포도 동일한
검사를 통과해야 합니다. 실제 Access/Refresh Token, 거래소 API Key/Secret, AWS 자격증명,
Google Client Secret, 인증서·키 파일·APK·로그·실제 `.env`는 커밋하지 않습니다.
API 주소와 비밀키 없는 Cognito App Client ID는 브라우저가 접속하는 공개 설정값입니다.
비밀정보 취급 원칙은 [SECURITY.md](SECURITY.md)를 따릅니다.

## 체결 차트 조작

- MA 체크박스 바로 아래의 `15m`·`1h`·`4h`·`1d` 버튼으로 차트 표시 주기를 바꿉니다. 처음에는 분석 주기를 선택하며, 변경할 때 선택한 십자선 또는 보고 있던 중앙 시점 주변을 표시합니다. 분석 설정·이력·수익률은 다시 계산하거나 변경하지 않습니다.
- 주기별 공개 캔들은 IndexedDB에서 재사용하고 없는 구간만 조회합니다. 실제 매수·청산 가격과 원래 신호의 가격선·파동은 보존합니다. 알려진 체결 시각으로 마커를 배치하며 봉 마감 체결은 막 끝난 봉에 표시합니다. 상세 시각이 없는 구형 서버 체결은 원래 기록된 봉 시각을 기준으로 하며 분봉 시각을 추정하지 않습니다.
- 완성봉만 표시하며 조회 실패 시 기존 차트·선택 주기를 유지해 다시 시도할 수 있습니다. 처음 주기로 돌아와도 원래 체결 봉 위치를 복원합니다.
- 차트를 열면 최초 진입 캔들을 화면 중앙에 표시합니다. 차트 바로 아래 오른쪽에 실제 `매수가`·`청산가` 링크를 표시하며 각각 최초 진입·최종 청산 캔들로 이동합니다. 캔들 정보가 숨겨져 있어도 두 링크는 표시합니다.
- 두 가격은 실제 체결 원장과 마커를 사용합니다. 청산가는 부분 TP·SL·TP 설정값을 대신 쓰지 않으며 최종 청산 체결이 없으면 `—`로 표시합니다. 처음 읽은 범위 밖이면 해당 시점의 캔들 페이지를 캐시에서 읽고 없는 구간만 조회합니다.
- 세로축과 거래량은 화면에 보이는 캔들 구간에 자동으로 맞춥니다. 거래량 영역은 64.8px(이전 72px의 0.9배)이며 줄인 7.2px 전부를 가격 캔들 영역에 배분합니다. 먼 주문 가격은 축을 늘리지 않으며 가시 영역 밖의 주문선은 그리지 않습니다. 하단의 매수가·SL·TP 범례는 제거했습니다.
- 두 손가락을 벌리면 캔들이 확대되고, 오므리면 축소되어 더 많은 캔들이 보입니다. 손가락 사이의 캔들을 중심으로 확대·축소하며 세로축도 다시 맞춥니다.
- 짧게 터치하면 십자선과 오른쪽 가격, 차트 아래 캔들 정보를 표시합니다. 이 상태에서 드래그하면 차트는 고정되고, 기존 교차점을 기준으로 손가락 이동 방향·거리만큼 선택 위치가 이동합니다. 손가락을 대는 순간 그 위치로 튀지 않습니다.
- 다시 짧게 터치하면 십자선을 닫고, 좌우 드래그로 차트를 이동할 수 있습니다.
- 팝업은 바깥 여백·테두리·둥근 모서리 없이 페이지 전체를 채웁니다. 기기의 안전 영역을 반영하고 제목·시간·범례의 안쪽 여백을 줄였습니다. 브라우저 주소창은 그대로 사용합니다.
- 차트는 300px 높이 제한 없이 MA 선택·캔들 정보·체결 링크를 제외한 남는 높이와 전체 너비를 사용합니다. 캔들 정보 공간을 확보하므로 십자선 표시·숨김으로 차트의 화면상 Y 위치·높이·가시 구간이 바뀌지 않습니다. 매우 낮은 화면에서는 팝업 내부를 스크롤할 수 있습니다.
- 차트 배경에서 시작한 의도적인 터치만 팝업을 닫습니다. 같은 차트 이력 항목의 중복
  popstate 알림이나 차트를 연 직후 이어지는 터치는 팝업을 닫지 않습니다.
- 차트의 왼쪽 끝에 도달하면 과거 캔들을 자동으로 불러옵니다. 로컬 결과 차트는 같은 IndexedDB 캔들을 재사용하고 부족한 구간만 공개 API에서 받습니다.
- 이동평균선 5개 체크 상태는 변경 즉시 localStorage에 저장합니다. 종목·전략을 바꾸거나
  차트·페이지를 다시 열어도 마지막 선택을 복원하며, 같은 Chrome 프로필의 다른 탭에도 반영합니다.
- 종목명·시간의 기본 문단 여백과 이평선 패널 간격을 줄여 캔들 차트가 더 위에 보이도록 합니다.
- MA5·MA10·MA20·MA60·MA120 체크박스는 320px 화면에서도 한 줄로 표시합니다. 이평선 패널 제목·터치 안내는 제거하고 가격 차트/거래량 사이 여백을 줄였습니다. 몸통·최대 등락률은 한 행, 캔들 정보의 MA별 수치는 두 항목씩 표시합니다.
- 십자선의 날짜·OHLC·등락률·거래량은 17.28px, MA별 수치는 화면 폭에 따라 14.4~17.28px로 v2.10.33의 0.96배입니다. 매수가·청산가 링크는 v2.10.34 대비 8% 키운 `clamp(13.608px,3.888vw,15.552px)`이며 오른쪽에 따로 배치해 정보와 겹치지 않습니다.
- MA 각도는 현재봉과 이전 2봉의 MA 값으로 `atan((MA[t]÷MA[t−2]−1)×100÷2)×180/π`를 계산합니다. 1봉당 1% 상승을 +45°로 정한 고정 척도이며 상승 +·하락 −입니다. 가격 단위·화면 세로축·확대/축소와 무관합니다. 세 MA 값이 모두 유효할 때만 표시합니다.

## 이력 설정

이력 카드를 선택하면 해당 기록의 종목·방향·주기·기간·수치와 체크박스를 입력폼 및 마지막 설정에
복원하고, 기록된 결과를 즉시 표시합니다. 늦게 도착한 최신 작업 조회가 선택한 이력을 덮어쓰지 않습니다.
서버 작업 이력의 설정은 현재 수정 중인 폼 대신 해당 작업의 요청값으로 저장합니다.
새 필드가 없던 예전 이력은 기본값으로 보완합니다. 단, 예전에 잘못 기록된 값은 원본 없이 복구할 수 없습니다.
CSV 파일 분석 버튼과 파일 선택 입력은 제거했습니다. 개별 종목의 공개 캔들 분석과 AWS 분석은 유지합니다.

## GitHub Pages 설정

배포 워크플로에는 현재 배포된 공개값이 기본값으로 들어 있습니다. 필요하면 저장소 Settings → Secrets and variables → Actions → Variables에서 아래 공개 변수로 덮어쓸 수 있습니다.

```text
VITE_API_BASE_URL=https://qsytnyfa5c.execute-api.ap-northeast-2.amazonaws.com/dev
VITE_COGNITO_DOMAIN=https://<project>-<environment>-<account-id>.auth.ap-northeast-2.amazoncognito.com
VITE_COGNITO_CLIENT_ID=<CognitoWebAppClientId 출력값>
```

선택 변수는 기본 Pages 주소를 사용하므로 보통 생략해도 됩니다.

```text
VITE_COGNITO_REDIRECT_URI=https://kdmerit.github.io/ZetaAuto-web/
VITE_COGNITO_LOGOUT_URI=https://kdmerit.github.io/ZetaAuto-web/
```

## AWS/Cognito 설정

`infrastructure/template.yaml`의 Google federation을 활성화할 때 다음을 함께 설정합니다.

1. `WebOAuthCallbackUri`와 `WebOAuthLogoutUri`를 `https://kdmerit.github.io/ZetaAuto-web/`로 등록합니다.
2. Google OAuth 콘솔의 승인된 리디렉션 URI에는 Cognito의 `/oauth2/idpresponse` 출력값을 등록합니다.
3. `AllowedEmailSha256`에는 `kdmerit@gmail.com`의 SHA-256 값 `cea3a87911783e6c41d2ef2cdf2b5091b2a965a27a058882aeb5aa707234d32b`를 사용합니다.
4. 스택 출력 `CognitoWebAppClientId`를 `VITE_COGNITO_CLIENT_ID`에 넣습니다.

Cognito PreSignUp Lambda의 서버 allow-list가 실제 접근 통제이고, 웹앱도 토큰 이메일이 `kdmerit@gmail.com`이 아닐 경우 세션을 폐기하는 보조 검사를 수행합니다.
